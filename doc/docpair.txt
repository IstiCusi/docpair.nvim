*docpair.nvim* *docpair*                                  Last change: 2026-11-17

docpair.nvim: managed source/notes window pairs. Tested with Neovim 0.12.6.

COMMANDS                                                *docpair-commands*

:Documented[!] [file] [infofile]                          *:Documented*
    Pair the named source or active file buffer with its notes. Source left,
    notes right. Without ! use a new tab; ! preserves the current tab and
    unrelated windows. Repeating on the current pair extends blank padding
    without resetting the cursor or adding more windows.

    Notes: <source-directory>/.documented/<source-basename>_info
    Custom infofile: use its basename in the same directory.
    Non-writable source directory fallback:
        ~/.config/docpair/tree<absolute-source-directory>/<notes-name>

:DocumentedClose                                         *:DocumentedClose*
    Close the current pair without forcing a modified buffer closed.

:DocumentedDetach                                        *:DocumentedDetach*
    Keep both windows, stop managing this view, restore saved window options.
    Use :Documented! to attach the view again.

:DocumentedRepair                                        *:DocumentedRepair*
    Reconcile registered pairs after commands that suppressed editor events.

CONFIGURATION                                           *docpair-setup*
>
    require('docpair').setup({ info_filetype = 'markdown' })
<
Native package loading runs setup with defaults. The only option is the notes
filetype, default markdown. Plugin use requires no Python dependencies.

NAVIGATION                                              *docpair-navigation*

Selecting another file within either pane updates the pair. :bnext skips notes.
Splits and tab splits of registered files receive their own partner. Several
pairs may exist in one tab. Tabs retain their own cursor/view positions while
sharing buffer contents. Help, quickfix, preview and floating windows are not
paired. Ordinary unregistered files outside a pair remain unaffected.

Vertical scrolling and cursor rows follow only the partner, including the mouse
wheel over an unfocused pane. Horizontal scrolling and cursor columns stay
independent. Wrap, folds and concealment are disabled in paired windows.

:only retains a complete pair. :close and :q in a pane close the pair, subject
to native checks for unsaved changes. :q on the final pair exits Neovim.
:tabclose and :tabonly do not recreate removed tabs. Ctrl-W T moves a paired
view to a new tab with its partner. Deleting a paired buffer removes its views.

SAVING AND SESSIONS                                      *docpair-saving*

Opening uses loaded buffers, including unsaved edits. It never writes source
or notes to disk. Missing trailing note lines are padded in memory. Existing
notes become modified if padding is added; a new empty padded notebook does not
count as a user edit. Run :Documented again after source growth to extend it.

:write saves the current pane; :wall saves all modified files, including hidden
notes. Edited notes survive switching even with nohidden. :qall refuses to
lose unsaved notes; explicit forced native commands keep their normal meaning.
The notes directory is created on first write.

:mksession creates <session-file>.docpair.json with file associations only.
:source of that session restores pairs and custom note paths. Unsaved contents
are not stored in the JSON; save your work separately.

:file and :saveas retain the association with the renamed buffer. The partner's
path stays unchanged, and no files are moved or copied. Use a session to retain
such non-default mappings between editor runs. One notes file cannot belong to
two sources at once, including when reopening an old source name after rename.

LIMITATIONS                                             *docpair-notes*

Line N maps to line N, not to a symbol. Inserting/deleting code can detach an
explanation from its intended function. Padding only extends the notes length.

Both whole files stay loaded; long notes are not a scope-limited projection.
Markdown syntax is supported, but rendered Markdown can break visual alignment.

Neovim still has two ordinary buffers/windows. Manual rearrangement can change
the geometry while preserving ownership. Small screens may have no room for a
partner split. noautocmd, session managers that skip native session events and
plugins replacing layouts may need DocumentedRepair or dedicated integration.
Symlink aliases are not canonicalized. Only Neovim 0.12.6 is validated here.

Comment projections, semantic anchors and multiple documentation providers are
not implemented by this lifecycle fix.
