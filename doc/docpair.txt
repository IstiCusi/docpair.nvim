*docpair.nvim* *docpair*                                  Last change: 2026-11-18

docpair.nvim: paired source, comment projections and external notebooks.
Requires Neovim 0.10+. Validated with 0.10.4, 0.11.5 and 0.12.6.
Whole-line hiding requires 0.11+. On 0.10 source comments remain visible.
:checkhealth docpair reports the running version, executable and features.

COMMANDS                                                *docpair-commands*

:Documented[!] [file] [infofile]                          *:Documented*
    Open source left, documentation right. No !: new tab; !: current window.
    Default view is text. An explicit infofile selects the external notebook.
    Ordinary registered source and documentation views stay paired across
    buffer changes, splits, tabs, close/only commands and native sessions.

:DocumentedView [text|markdown|raw|notes]                 *:DocumentedView*
    Select an enabled view, or cycle configured views if no name is given.
    Default normal-mode key in the documentation pane: g<Tab> (g, then Tab).

:DocumentedAdd                                           *:DocumentedAdd*
    Create/open a comment associated with the code cursor and focus its view.
    Default source mapping: <leader>dd. Syntax nodes determine safe insertion
    when available; fallback inserts before a whole source line. Known string
    interiors and explicit line continuations reject insertion.

:DocumentedSource                                        *:DocumentedSource*
    Reveal/hide comments in this pair. Default source mapping: <leader>ds.

:DocumentedDiscard                                       *:DocumentedDiscard*
    Explicitly discard an unapplied draft and reread the source comment.

:DocumentedDrafts                                        *:DocumentedDrafts*
    Select an unapplied draft to reopen after switching files.

:DocumentedClose                                         *:DocumentedClose*
    Close the current pair, subject to normal modified-buffer protection.

:DocumentedDetach                                        *:DocumentedDetach*
    Keep panes, release this pair, restore the original window options.
    An open comment projection still writes its source. :Documented! re-pairs.

:DocumentedRepair                                        *:DocumentedRepair*
    Repair registered views after operations that suppressed normal events.

CONFIGURATION                                           *docpair-setup*
>
    require('docpair').setup({
      initial_view = 'text',
      views = { 'text', 'markdown', 'raw', 'notes' },
      mappings = {
        cycle = 'g<Tab>',
        create = '<leader>dd',
        source = '<leader>ds',
      },
      comments = { hide = true, debounce_ms = 80 },
      info_filetype = 'markdown',
      on_markdown = false,
    })
<
Use the same table as lazy.nvim's opts. Mapping false disables a default key.
The views list replaces the cycle order. initial_view must be included in it.
initial_view='notes' retains the previous notebook-first workflow.
on_markdown may be a function(buffer, window) for optional renderer integration.
Markdown itself uses Neovim highlighting/concealment; no rich renderer is bundled.

VIEWS AND SAVING                                        *docpair-saving*

text:       comment body, no language-specific wrapper.
markdown:   same body with Markdown filetype, syntax and concealment.
raw:        exact comment including its delimiters.
notes:      external per-source notebook, preserving the earlier line coupling.

The complete ordinary source buffer is authoritative. No projection files are
written. Changing view does not modify source or create a source undo entry.
:write in a comment pane flushes pending changes and saves the entire source.
:write in notes writes that notebook. :wall saves all modified files.
Rename / :saveas the source, not a projection. Opening alone never writes files.

Normal u/Ctrl-R in a comment pane use source undo/redo. Continuous insertion is
joined while no other source edit intervenes. Source-window undo stays native.

Conflicts, missing ranges and unsafe delimiters retain a modified draft instead
of overwriting source. Repair it or explicitly :DocumentedDiscard. View changes
are blocked until repaired. :DocumentedDrafts reopens hidden drafts. Forced quit
commands may discard unsaved text. No crash guarantee is made for unflushed
projection drafts; applied changes live in the ordinary source buffer.

Notes path: <source-directory>/.documented/<source-basename>_info.
A custom infofile uses only its basename. Non-writable source directories use
~/.config/docpair/tree<absolute-source-directory>/<notes-name>.
Notes are loaded/padded on use and written on save. Hidden edited notes take
part in :wall and native unsaved-buffer checks.

SCOPES AND NAVIGATION                                   *docpair-navigation*

Whole-line standalone comments are recognized by language adapters. Available
Tree-sitter parsers supply syntax scopes. The smallest documented section wins.
Without a parser, nearest preceding comment is the positional fallback; the
window bar distinguishes it from syntax scope. Unknown filetypes can use notes.
Trailing comments, recognized directives and Python docstrings remain source.

Comment-pane scrolling never moves the source cursor. Selecting another source
section changes the comment view and restores that section's reading position.
While editing documentation, its section is fixed. A D sign marks hidden docs.

Code-window concealment changes only display. Physical ranges, line numbers,
substitutions and copy/delete operations still include comments. Reveal source
before moving functions and their docs. The cursor skips hidden comment lines;
reveal source to inspect exact search hits. Other windows of the same buffer
remain visible. Comment-only files keep a visible source position.

Each source view has its own paired documentation window. Several pairs may
exist in one tab, or show the same source in different tabs and modes. Native
splits, tab splits, buffer switches, :only and Ctrl-W T keep pairs intact.
:close/:q close a pair; :tabclose/:tabonly do not resurrect removed tabs.
Deleting a paired buffer removes its pair. Unrelated/help/quickfix/float windows
remain independent. Symlink aliases are not canonicalized.

SESSIONS                                                *docpair-sessions*

:mksession writes a <session>.docpair.json companion with associations, modes
and positions, not content backups. :source restores the native session and
its comment views. Save files first. An invalid draft blocks restoration.

LIMITS                                                  *docpair-notes*

Fallback scope association is positional, not semantic. Install a Tree-sitter
parser for the source language. Lexer adapters cannot cover every dialect or
embedded language. XML/Javadoc/reStructuredText are preserved, not converted.
Python docstrings are strings, not projected comments in this version.

External notebooks retain line-number alignment, so edits to source can make
old note positions drift. Markdown comment views have no line-alignment limit.

These are normal Neovim windows coordinated by the plugin. Small screens may
prevent splits. noautocmd, session tools omitting native events, or plugins
replacing the layout may need :DocumentedRepair or a dedicated integration.
Hiding uses Neovim 0.11's window-scoped namespace API. Older editors keep
source comments visible. Below 0.10 the plugin stays disabled at startup;
:Documented explains the minimum. Check :version and :echo v:progpath.
